# Сервер распознавания GigaAM (свой)

`gigaam-server.mjs` — тонкая обёртка вокруг GigaAM v3 CTC (с пунктуацией)
через `sherpa-onnx-node`. Мы держим её отдельным процессом на Node, потому что
плагину голосового режима нужен обычный HTTP-сервис, а не встроенный
распознаватель.

## Что важно знать

- **Модели в репозитории нет.** Веса GigaAM — собственность Сбера, их надо
  получить отдельно (Hugging Face: `gigaam`). Сюда кладутся только код и
  инструкция.
- Нужен `sherpa-onnx-node` (нативная сборка) — ставится рядом с проектом,
  как обычная npm-зависимость.
- Нужен частотный словарь русского языка `ru-frequency.txt` — он используется
  для исправления «почти правильных» слов (`spellcheck`). Подойдёт любой
  частотный список в формате `слово число` построчно; без файла сервер
  работает, но проверка слов отключается.
- Модель, которую мы используем: `gigaam-ctc-punct` — она сама ставит точки,
  запятые и заглавные буквы, отдельный пунктуатор не нужен.

## Контракт

Сервер отвечает ровно так, как ожидает провайдер `sensevoice` из плагина
`@goodandready/dsh-voice`:

```
POST /            multipart/form-data, поле "file" = WAV 16 кГц моно, 16 бит
  -> 200 {"text": "..."}

GET  /            200 — проверка живости
```

## Переменные окружения

| Переменная | По умолчанию | Что значит |
|---|---|---|
| `GIGAAM_DIR` | `<DSH_VOICE>/models/gigaam-ctc-punct` | папка с `model.int8.onnx` и `tokens.txt` |
| `GIGAAM_DICT` | `<папка скрипта>/ru-frequency.txt` | частотный словарь для проверки слов |
| `GIGAAM_PORT` | `6006` | порт HTTP |
| `GIGAAM_HOST` | `127.0.0.1` | адрес прослушивания |
| `GIGAAM_THREADS` | `4` | число потоков модели |
| `GIGAAM_MAX_BYTES` | `33554432` | предел размера загружаемого WAV |

## Запуск

```bash
node gigaam-server.mjs
curl http://127.0.0.1:6006/          # {"ok":true,"provider":"gigaam-v3-ctc-punct"}
```

В плагине провайдер распознавания указывает на этот адрес:
`stt: { provider: 'sensevoice', url: 'http://127.0.0.1:6006' }`.

## Что внутри, кроме обёртки

- `fixQuestion` — если последнее предложение реплики звучит как вопрос
  (вопросительное слово в начале, частица «ли», глагол во втором лице в конце),
  точка меняется на вопросительный знак. Модель иногда ставит точку.
- `spellcheck` — исправляет слова, где распознаватель ошибся в гласных
  (е/и, о/а, я/е, ё/е) или в мягком знаке, но только если исправленное слово
  есть в частотном словаре. Общий поиск по расстоянию Левенштейна специально
  не используется: он придумывает несуществующие слова.
- `fixWord`, `candidates` — вспомогательные функции для этой проверки.

## Если что-то не работает

- `EADDRINUSE` в журнале — порт занят старым процессом: `taskkill /F /PID <pid>`
  по владельцу 6006 и запуск заново.
- Сервер отвечает 500 на длинных файлах — скорее всего, пришёл звук не 16 кГц
  моно: `/api/v1/asr` принимает только 16 кГц (`expected 16 kHz audio`).
- Пустой текст на коротких записях — нормально: обрывки короче 0,4 с в плагине
  отсекаются ещё до отправки.
